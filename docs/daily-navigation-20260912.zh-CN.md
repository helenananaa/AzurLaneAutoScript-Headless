# 每日挑战入口转场修复（2026-09-12）

原生 `UI.ui_ensure(page_daily)` 从主页进入每日页后，可能继续用过渡前的出击菜单识别结果，再次请求 `CAMPAIGN_MENU_GOTO_DAILY`。实机初次诊断在已经进入每日页后报 `campaign daily entrance is not actionable`，见 `integration/alas/daily-other-20260912/overview.log` 与 `settled.json`。

适配层现在保留真实入口回执。只有最新状态确认每日页存在、返回控件唯一可见且无遮挡、代次晚于回执时，才确认重复入口请求已完成，不再次点击被遮挡的出击菜单。若入口检查期间发生转场，仅在没有新增输入且目的地检查通过时复用回执；已经发出输入的异常继续上抛。重置任务状态会清除回执。原生导航、循环、调度和快速挑战流程未修改。

现场商船护送、海域突进均显示 3/3，但两者都有锁定标记；战术研修、斩首行动已是 0/3，其他可见挑战也为零。未因显示剩余次数就执行锁定挑战。本次目标是入口导航，批量快速挑战的连续领奖资格仍待可用日次数。

测试：25 项入口转场/科研入口/每日快速边界检查通过，41 项基础适配与任务隔离检查通过。没有修改 ALAS 补丁系列或观察器，无需重新构建 APK。实机使用前一轮已安装的 r5 观察器。

复用入口：`scripts/python/run_alas_daily_navigation_live_validation.py`。它调用原生 UI 完成两轮主页与每日页往返，记录真实入口回执，并在每日页重复请求入口，检查零额外输入。失败证据保留，不伪造成功。

首轮修复验证 `navigation-r1.json` 保留失败：到达检查错误使用通用 enabled，而每日返回属于专用端口，未知命中不代表页面未到达。新增的到达观察不执行输入；None 命中可用于页面身份观察，明确 false、重复目标、遮挡和战前页均拒绝复用。新的输入仍由原有专用端口负责。

`navigation-r2.json` 的第一轮完整往返通过：一次真实每日入口、显式重复请求零输入、回主页。第二轮进入后，通用页面扫描查询未激活船坞流程的 `DOCK_CHECK` 而停止。现将明确、无遮挡的每日页作为页面扫描归属，仅 `DAILY_CHECK` 为真，其余页面标记为假；不要求启动船坞任务，不关闭独立船坞能力。最终聚焦回归 67 项通过（`tests-final.log`），包含这项任务隔离场景。

最终 `navigation-r3.json` 为 passed=true：同一进程完成两轮原生主页→每日页→主页，每轮真实每日入口恰好一次，显式重复入口请求均为零额外输入。最终回到主页；钻石 5040、石油 6193、金币 32890，前后相同。锁定/零次数状态未被修改。支持仅增加导航证据，不提升完整批量快速领奖或全部星期类型。
