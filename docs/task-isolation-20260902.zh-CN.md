# ALAS 任务隔离修复与验证（2026-09-02）

本轮修复公共路由对无关任务解析器的依赖，并在原版 ALAS 的单次任务边界释放上下文。
已在同一游戏进程、同一 Session 中走通：受控能力失败 → 原版 ALAS 返回主界面 →
原版 Reward 任务正常结束。本次 Reward 关闭了所有领取选项，验证范围是任务切换和导航。

## 代码变化

- `oracle/surfaces.py` 提供浅层界面归属，`CoreOracle.observation_target_present()`
  读取原子入口。公共主界面返回、通用返回、商店/通行证/档案观察、弹窗及战斗兜底，
  不再为确认一个功能缺席而进入该功能的详细解析器。
- 舰队通知在主界面快速判断之前遮住下层页面。奖励侧栏在保留主界面节点时优先归属
  `REWARD_CHECK`，避免 ALAS 反复切换展开按钮。侧栏已经关闭且新鲜状态证明主界面
  可操作时，重复返回请求只返回既有的 `main/already` 观察回执，不再注入输入。
- `adapter/task_lifecycle.py` 接入补丁 `0510-semantic-task-isolation.patch`。
  ALAS 继续拥有任务选择、导航、失败间隔、重启、重试和成功判断。
- 任务结束会释放上下文、待执行意图、结果归属和借出的帧；动作额度、已消费额度、
  运行身份、输入 generation 失效记录、已完成回执保留。清理不会重新授予动作额度。
- 源码枚举包含新任务边界，后续验证不再只记录两个公共入口文件的哈希。

| 结果 | 原版 ALAS 如何继续 |
| --- | --- |
| `AlasSemanticUnmapped`、`UnknownObservationError`、`UnsupportedPixelRead` | 该任务延后，使用原有 FailureInterval；不记成功，不累加客户端崩溃次数 |
| 正常返回、`TaskEnd` | 保留原来的成功处理，清理任务状态 |
| ALAS 已知的游戏未运行等异常 | 保留原来的 Restart/恢复处理 |
| 身份错误、过期帧、歧义、输入结果不确定、未分类代码错误 | 保留原来的失败/停止路径 |

这是已分类兼容性失败的局部隔离。所有任务仍共享游戏进程和运行时；无法识别或无法安全
离开的界面、运行时本身的故障仍可能阻止后续任务。没有增加第二套任务状态机或像素回退。
