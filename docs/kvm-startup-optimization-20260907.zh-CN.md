# KVM 控制命令启动优化与登录前资源观测

本轮缩短了日常控制命令的加载时间，并增加启动分段计时。未重编 Android、
修改镜像校验策略、调整默认 guest 内存或登录账号。

## 已实施

- 根包原先无条件加载整套 ALAS 公共导出，即使调用者只运行 KVM Status。
  原导出声明原样迁入 `_public_api.py`，根包通过标准模块 `__getattr__` 按需
  加载；直接导入运行时子模块不会初始化整套统一 API。显式导入、`import *`、
  对象身份和 `dir()` 发现保持兼容，类型检查器仍可发现公开导出。
- Windows 入口将四次 WSL 路径转换合并为一次调用，路径作为独立参数传入。
  使用 `--exec`，避免再经过 Linux shell 解析。已检查包含空格的配置路径。
- `ready` 的 JSON 输出增加 `timings_seconds`：等待 ADB、等待 Android/网络、
  游戏冷启动、等待可用状态及总耗时。这些是观测值，不是新的运行门槛。

镜像每次启动的完整验证、实际 VHDX 挂载检查、设备/console 身份核对、
Unity 冷启动参数和正常停机路径均保留。

## 测量结果

Status 对照均在同一 WSL 环境保持运行、同一 AVD 停止状态下执行。
两组各两次，路径转换已经合并；因此这组差值主要反映统一 API 的按需加载。

| 项目 | 观测 |
| --- | --- |
| 修改根包前 Status | 5.522、4.787 秒，中位数 5.154 秒 |
| 修改根包后 Status | 2.775、2.424 秒，中位数 2.599 秒 |
| 本组相对缩短 | 约 49.6% |
| Android-only Start 总时间 | 61.613 秒 |
| 其中等待 ADB | 26.150 秒；包含该阶段尚未完成的模拟器启动工作 |
| 等待 Android 与网络就绪 | 25.087 秒 |
| 在已启动 Android 上启动游戏 | 入口总计 21.935 秒 |
| 其中游戏启动调用 / 等待语义状态 | 3.174 / 16.141 秒 |

最初一次未保持 WSL 活跃的 Status 约 9 秒，不混入上述成对比较。
这些少量样本不能作为通用延迟承诺。Android-only Start 时同时运行了离线
回归，其时间不用于声称 Android 内核或镜像启动变快。

## 资源观测

完整回归结束后，分别在 Android launcher 和原生 SDK 登录页各取 20 秒样本，
前后状态及 Emulator PID 一致：

| 场景 | Emulator 平均 CPU（等效逻辑核） | Emulator RSS |
| --- | ---: | ---: |
| Android 空闲 | 0.107 | 约 2.44 GiB |
| 原生手机号登录页 | 0.714 | 约 3.84 GiB |

RSS 是整个宿主 Emulator 进程的驻留内存，不等于 Android 应用独占内存。
SDK 登录页时 Unity 暂停导出，不能把该场景外推为 ALAS 日常、战斗或多实例
容量。因此默认 guest RAM 仍为 3072 MiB；进一步降低它需要代表性的登录后
工作负载，而不能凭登录页能停留就认定安全。

两次观测均为 `Accounts: 0`，没有账号输入。完成后通过正常 Stop 停止实例，
AVD 与资源保留。

## 验证范围

- 公共 API：503 个显式导出、352 个星号导出的对象身份一致。
- Windows 完整仓库测试：2215 passed、8 skipped；约 355 秒。
- WSL 聚焦 API/日常入口/启动脚本：17 passed。
- 新入口实测完成 Android-only Start、游戏冷启动、Status 和正常 Stop。
- 没有修改 ALAS 任务支持等级，没有宣称登录后的性能或支持资格。

[收据与数值](../integration/runtime/kvm-startup-20260907/receipt.json)记录了本轮
原始数据位置；历史生命周期失败与修复证据继续保留。
