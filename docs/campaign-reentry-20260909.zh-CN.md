# 2026-09-09 取消战前页后的同格恢复

已在 10-2、第六舰队验证：原版 Main 进入 B6 战前页，在不开战的情况下取消，
新的原版 Main 进程恢复同一张地图，再次进入 B6 战前页并正常撤退。
RunCount 归零、调度关闭，最终回到主页。全程零战斗、零维修，入图消耗 10 石油。

## 根因与修复

原先的报错“enemy-covered input lacks one exact enemy”并非没有敌人。
取消战前页后，B6 的唯一敌人仍显示 `xingdongzhong / 行动中`，解析为 `fighting=True`；
输入端过滤掉所有这样的敌人，导致原版 ALAS 已选中的恢复目标无法重新进入。

现在仅在目标格有唯一敌人、唯一舰队占据该格且该舰队就是当前选中舰队时，允许此恢复分支。
别处的行动中标记不会全局阻止当前目标。原有新鲜帧、包/PID/前台、目标几何、预算和结果确认保持不变。

测试发现覆盖点击原先未识别 `ChapterPreCombatUI` 对地图的遮挡。
因此在已有最终状态读取中检查活动的战前／战斗层，拒绝穿透输入；不增加轮询、审批或启动门槛。
隐藏的旧层不阻挡，错误舰队、同格多个舰队、重复敌人和真实活动战前层均有定向覆盖。

## 证据与资源

[`integration/alas/campaign-reentry-20260909`](../integration/alas/campaign-reentry-20260909/) 保存：

- `pause.json`：原 Main 的首次战前现场和战斗准入，按验证安排暂停，原始 `passed=false` 保留。
- `cancelled-map.json`：真实返回地图收据，以及 B6 的“行动中”文本。
- `resume.json`：相同 PID、目标 B6、当前舰队与敌人同格的原始准入，以及重新进入、撤退和调度收尾。
- `assessment.json`：两阶段关联、源码哈希、资源与未完成范围。
- `dock-capacity-r2.json`：只读船坞容量 `914/930`，读取后返回主页，未选择或退役任何舰船。
- `ui-additional.json`：原版通用恢复探测在主页运行成功，输入次数为零。

243 项相关 Windows 回归通过。当前实机只验证一个行动中目标；无关格的行动中状态不阻断当前目标，
属于离线兼容覆盖。没有证明所有关卡、舰队或敌人类型的恢复。

返回主页时另发现 `ui_additional` 无 Campaign 上下文却探测 `MAP_PREPARATION` 等资源的错误。
已补充无遮挡主页／出击菜单上的明确负向观察，实际弹窗仍保留其原处理边界。
