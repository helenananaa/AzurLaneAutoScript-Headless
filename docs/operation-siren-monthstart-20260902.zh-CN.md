# 大世界月初开荒适配（2026-09-02）

本次补齐真实月初入口，并用当月重置后的危险海域验证原 ALAS 开荒流程。
过去的 72 海域记录全部是 SAFE 遍历，其中的“月度重置”指任务游标与下次运行时间重置，不能证明游戏月初重置或危险海域开荒。

## 实现

- 原 `ui_page_os_popups` 处理兑换券结算、舰队准备和免费打开特别兑换商店的提示；适配器只提供相应 typed 观察和输入。
- 原 `storage_sample_use_all` 保留六类样本的顺序，将像素匹配替换为物品 ID、sprite、数量和可操作性识别；物品使用继续调用未改动的 `_storage_item_use`。使用后必须证明对应库存减少。
- 物品详情页支持游戏实际发生的父节点迁移；输入使用当前 typed bounds 的内部，避免 RectTransform 锚点落在按钮边缘。
- 恢复锁区检测，使原 `OSExploreError` 返回纽约的逻辑继续生效；普通海域入场前再次核对目标名称，坐标海域保留自身的特殊 pin 身份。
- 地图选点、取消选中和输入后的刷新等待真实的新 generation，避免较慢观察器把前一次操作的结果归给下一次操作。
- 仓库退出等待其 overlay 消失；地图就绪排除仍在前台的仓库、指令和奖励面板，启动时恢复残留仓库。断点恢复到当前危险海域时，继续走原海域类型检查，不能仅因“已经在目标海域”就写成已清理。

## 继续验证与使用

正常开荒验证配置保存在独立 ALAS 工作树的 `config/monthstart.json`，首轮结束断点为 24；后续进展与最终断点见[续跑报告](operation-siren-monthstart-continuation-20260902.zh-CN.md)。开荒调度器关闭，验证也未启动总调度循环。原 ALAS 配置仍保留 Restart、Commission、Research、Reward 四项基础任务的 Enable=true，不应直接将这个验证配置作为无人值守总调度启动。保留开荒断点即可继续原顺序；不要为了重跑而随意改成后面的海域。

可用 `scripts/python/run_alas_opsi_monthstart_live_validation.py` 对独立配置执行 `--mode explore` 或 `--mode samples`。前者在一次危险海域完成后的原任务切换处停止；后者只有实际减少非零样本库存才通过。`--sample-source-zone` 只用于独立取样配置，并明确记录自定义验证顺序，不能用于证明完整原顺序遍历。

本次没有证明月末 `OpsiCrossMonth` 整任务、全部 72 个危险海域、全部舰队/潜艇组合或购买记录仪分支。支持表继续保持按证据范围描述，不提升为全配置支持。

驱动升级仅替换 `org.chromium.angle`，没有清除游戏数据。安装后的 APK SHA-256 已核对为 `04281ef4afa52427192680e498dd1ba0ffdbb278a1b6029a21b7a1026fd8306b`；原 APK 已保存为 `artifacts/monthstart-20260902/angle-before.apk`。所有启动均使用 `-force-gfx-st`。这份本地运行证据不代表 native-Linux Redroid 的资格证明，也没有改动项目固定上游锁。
