# META 奖励页面纠错与未解锁阶段验证

本轮发现此前“无奖励”并不可信：`META_CHECK` 把 WorldBoss 战斗页面当成了科研菜单中的 META 同步页面。原生 `MetaReward.run()` 因而在错误页面等待，超时后记录无奖励。

实机确认了两个不同页面：

- `WorldBossUI/WorldBossAwardUI` 是支援目标的奖励预览，显示“同步值：萨拉托加·META”，没有领取操作。专用 `meta/reward-preview/open` 只作为已审查的预览端口，**没有绑定到 ALAS 的 `REWARD_ENTER`**。
- `MetaCharacterUI` 是科研菜单进入的 META 同步页面。当前实际进度为 **1830/2000**，控件是 `ShowWayBtn` / `PreviewBtn`，对应 `ptpanel_btn_showway` / `ptpanel_btn_preview`。这才是本轮验证的未解锁阶段。

## 代码与实机结果

1. `META_CHECK` 只识别真实同步页面，不再把支援列表视为同一页面；通用页面扫描在此页面明确识别所有者，避免触发无关 `FLEET_CHECK`。
2. 从明确的两个控件、精确进度文本和一致代次读取未解锁状态。原生 `SYNC_ENTER` 分支通过，当前奖励提示为 false。达到观察到的门槛、缺失控件、畸形进度或结构变化均报告该奖励阶段未适配，不会假装无奖励。
3. 原生 `MetaReward.run()` 实机正常结束，`meta_wait_reward_page` 直接在 `SYNC_ENTER` 结束，**没有等待超时**；前后进度都为 1830/2000。
4. 补齐同步页面返回端口，要求当前同步页面、精确共享顶栏返回按钮、可操作状态、前台与遮挡检查；共享顶栏在其他页面出现不授权该端口。

原生 UI 已经由同步页、科研菜单返回主界面。最终 68 项聚焦回归、支持矩阵及配置攻击矩阵校验通过。

预览入口曾以临时 `REWARD_ENTER` 绑定作现场验证；`open.json` 保留了该探索时的原始回执。打开后确认其真实语义为预览，最终代码已撤销该错误绑定。该历史回执不能用于证明原生领奖入口受支持。

## 验证范围

未解锁且进度低于当前门槛的 **无奖励分支** 已验证。实际同步领取、解锁后的里程碑奖励及档案奖励仍未验证。支援列表到正确同步页的完整任务衔接也没有在本轮提升为支持；修正页面识别后不能沿用旧的“零次数完整任务成功”作为完整领奖证据。

当前还差 170 同步值达到页面显示的门槛；达到后才能验证下一阶段。本轮没有开战或领取奖励，也没有购买或消费高级货币。

观察器仅增加奖励预览按钮的原生命中导出；本机 WSL x64 NULL、J32 增量编译 12 步，10.95 秒。已安装 APK SHA256 为 `8ba551b7791d13f7d2334fde8c956e116d882a6b4291b5633ee60eb5f4062992`，与设备安装包一致。产物在 `artifacts/meta-reward-20260912/observer.apk`；上一版 `artifacts/daily-meta-20260912/observer.apk` 保留，本轮未验证回退。

证据位于 [meta-reward-20260912](../integration/alas/meta-reward-20260912/)：`open.json` 为奖励预览；`character-page.json` 为真实同步页；`pending-sync-live.json` / `.log` 为原生无奖励分支；`return-main-r2.json` / `.log` 为返回验证；测试及支持矩阵校验见最终日志。失败导航和登录尝试保留，未改写成通过。
